# 项目结构说明

本项目是一个基于 Netty 的轻量级 RPC 框架，采用 Maven 多模块组织。核心模块提供网络通信、编解码、序列化、服务注册与发现、负载均衡等能力；并通过 Spring Boot Starter 提供开箱即用的注解与自动装配；同时配套示例 Provider/Consumer 应用与独立测试模块。

- JDK 版本：Java 8
- 架构要点：Netty 通信、自定义二进制协议、可插拔序列化、可插拔注册中心、可插拔负载均衡
- 注册中心：Zookeeper、Nacos、Consul（默认 Nacos）
- 序列化：JDK Object、Fastjson、Hessian、Kryo（默认 Kryo）

## 顶层结构

- 根 POM（pom.xml）为聚合工程，声明模块：srpc、springboot-starter-srpc、srpc-test
- srpc-provider、srpc-consumer 为独立示例应用（未纳入根 modules 中）

目录一览（省略无关文件）：


## 模块详解

### 1) srpc（核心框架）

职责：提供客户端/服务端通信、自定义协议编解码、请求响应模型、注册中心与负载均衡等基础能力。

关键包结构：

- common
  - RPCRequest / RPCResponse：请求/响应通用模型
- codec
  - MyEncode / MyDecode：自定义二进制协议的编码/解码器
  - Serializer 接口与实现：ObjectSerializer、JsonSerializer、HessianSerializer、KryoSerializer
  - MessageType：消息类型标识（Request/Response）
- client
  - RPCClient 接口、NettyRPCClient、NettyClientInitializer、NettyClientHandler
  - RPCClientProxy：JDK 动态代理，拦截方法调用并封装为 RPCRequest
- server
  - NettyRPCServer、NettyServerInitializer、NettyRPCServerHandler
  - ServiceProvider：本机服务实现缓存与注册中心注册
- register
  - ServiceRegister 接口与工厂 ServiceRegisterFactory（zk / nacos / consul）
  - ZkServiceRegister、NacosRegister、ConsulRegister
  - InterfaceItem：服务实例元数据
- loadbalance
  - LoadBalance 接口
  - RandomLoadBalance、RoundLoadBalance（默认）、WeightBalance、MinConnectionBalance

默认策略：

- 注册中心默认使用 Nacos（见 ServiceRegisterFactory.NACOS）
- 序列化默认使用 Kryo（见 Netty 初始化代码）
- 负载均衡默认使用 RoundRobin

### 2) springboot-starter-srpc（Spring Boot 集成）

职责：提供注解与自动装配，简化 Provider/Consumer 的使用。

核心组件：

- 注解
  - @EnableRpc(needServer, host, port)：开关与基础配置
  - @RpcService：标记服务实现类（Provider 侧），自动注册
  - @RpcReference：注入远程服务代理（Consumer 侧）
- 启动与装配
  - RpcInitBootstrap：读取 @EnableRpc，初始化 ServiceProvider，按需启动 NettyRPCServer
  - RpcProviderBootstrap：BeanPostProcessor，扫描 @RpcService 并注册到注册中心
  - RpcConsumerBootstrap：BeanPostProcessor，扫描 @RpcReference 并注入代理（RPCClientProxy）
  - RpcClientFactory / ServerServiceProvider：单例工厂，复用客户端与服务端对象

使用方式（示意）：

- Provider 应用主类：@EnableRpc(needServer = true, port = 9999)
- Consumer 应用主类：@EnableRpc(needServer = false)
- 提供方实现类上标注 @RpcService；消费方在字段上标注 @RpcReference

### 3) srpc-test（独立示例/压测）

- 纯 Java 方式直连运行 Netty 的示例：TestServer、TestServer2、TestClient、MyTest
- 提供简单的 service 与实体用于验证编码/序列化/注册发现等流程

### 4) srpc-provider（示例 Provider 应用）

- Spring Boot 应用，演示如何通过 Starter 暴露服务
- 关键类：
  - SrpcProviderApplication（@EnableRpc(needServer = true, port = 9999)）
  - UserImpl：实现示例接口 com.sifan.boot.starter.User，并标注 @RpcService
  - service/dao/entity：演示与 MyBatis-Plus、数据库的集成

### 5) srpc-consumer（示例 Consumer 应用）

- Spring Boot 应用，演示如何通过 Starter 远程调用
- 关键类：
  - SrpcConsumerApplication（@EnableRpc(needServer = false)）
  - AppController：通过 @RpcReference 注入 User 接口并发起远程调用

## 端到端调用流程（概览）

1. Provider 启动
   - @EnableRpc -> RpcInitBootstrap 初始化 ServiceProvider 并按需启动 NettyRPCServer
   - RpcProviderBootstrap 扫描带 @RpcService 的 Bean，调用 ServiceProvider.provideServiceInterface 完成本机缓存与注册中心注册
2. Consumer 启动
   - RpcConsumerBootstrap 扫描 @RpcReference 字段，使用 RPCClientProxy 生成 JDK 动态代理
3. 发起调用
   - 代理拦截方法 -> 封装 RPCRequest -> Netty 客户端编码（MyEncode + 序列化）并发送
   - 服务端解码（MyDecode）-> 通过 ServiceProvider 找到实现 -> 反射调用 -> 封装 RPCResponse 返回
   - 客户端通过 NettyClientHandler 取回响应并返回给业务方

## 注册中心与负载均衡

- 支持 Zookeeper、Nacos、Consul，默认 Nacos；地址可通过系统属性或环境变量配置：
  - srpc.registry 或 SRPC_REGISTRY：nacos | zk | consul（默认 nacos）
  - srpc.zk.addr 或 SRPC_ZK_ADDR：ZK 地址，默认 127.0.0.1:2181
  - srpc.nacos.addr 或 SRPC_NACOS_ADDR：Nacos 地址，默认 127.0.0.1:8848
  - srpc.consul.addr 或 SRPC_CONSUL_ADDR：Consul 地址，默认 127.0.0.1:8500
- 负载均衡可选：随机、轮询、权重、最小连接数（默认轮询）。如需扩展，实现 LoadBalance 接口即可。

## 序列化与协议

- 默认序列化器可配置：srpc.serializer 或 SRPC_SERIALIZER（kryo | hessian | json | java），默认 kryo

- 支持 JDK Object、Fastjson、Hessian、Kryo（默认 Kryo）
- 自定义报文格式：messageType + serializerType + length + body
  - messageType：Request/Response
  - serializerType：序列化器类型编号
  - length：body 字节长度
  - body：序列化后的对象字节流

## 注意事项

- 启动前需确保注册中心已就绪，且地址与代码配置一致（目前使用内置默认地址）
- 端口与主机通过 @EnableRpc 传入；Starter 侧暂未提供外部化配置文件映射
- 示例 Provider/Consumer 作为独立工程运行，需先 install 根项目与 Starter
